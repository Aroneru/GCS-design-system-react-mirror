Component API Checklist

The compressed essence — scan this before shipping any shared component.

The props-API rules

RuleDo thisNot this
Use variants, not booleans, for >2 states variant="primary" | "secondary" | "ghost" isPrimary + isGhost + outlined
Give every variant/size a default variant = "primary", size = "md" Required props for the common case
Spread the rest onto the root element <button {...rest}> Hand-listing every native prop you support
Forward the ref to the DOM node ref reaches the real <button> Ref lost inside the component
Default to children for content <Button>Save</Button> label="Save" for arbitrary content
Export the prop type export type ButtonProps = … Prop type trapped inside the file
Merge, don't clobber, className `ds-btn ${className ?? ""}` Overwriting the consumer's class

The canonical shape (React 19 + TS)

// Extend the native element so consumers get every real attribute for free.
type ButtonProps = React.ComponentPropsWithoutRef<"button"> & {
  variant?: "primary" | "secondary" | "ghost";
  size?: "sm" | "md" | "lg";
};

export function Button({
  variant = "primary",
  size = "md",
  className,
  ...rest              // everything native: onClick, disabled, type, aria-*
}: ButtonProps) {
  return (
    <button
      className={`ds-btn ds-btn--${variant} ds-btn--${size} ${className ?? ""}`}
      {...rest}
    />
  );
}
The one-line test A design-system component is judged by its public interface, not its insides. If a teammate can guess the props without reading the source, the API is good.

Smell test before merging

❓More than 2 boolean props that affect appearance? → collapse into a variant.
❓Consumer can't pass onClick/aria-label? → you forgot ...rest.
❓Passing a ref does nothing? → forward it.
❓Content is a label string? → use children unless it's truly a single line of text.
